The server matches each request once with `route-table.ts`. Its stable route id selects a registration from the domain factories. Startup rejects missing, extra, duplicate or incompatible registrations. The shared policy checks caller, capability and the declared project resolver before console dispatch. Unknown edge paths and wrong methods never enter a protocol adapter.

`guards.ts` owns browser credentials, mutation proof and project admission. `runtime.ts` describes the captured state used by console factories; getters preserve mutable server state. `task-views.ts` contains task/result views shared by several domains. Rendering helpers and public server types remain in `shared.ts`. Domain handlers keep their original checks for state that can change after admission.

Remote adapters retain their protocol authentication and refusal formats. An async request context carries the matched row through that proof; `adapterPolicy` applies the same evaluator before protocol operations. CLI, MCP and team POSTs declare a read minimum and also check each decoded operation's capability. Their existing operation boundaries resolve project sets, object membership and current grants. Webhooks resolve the flow from the secret address; provider signatures remain required.

The old decision-answer row was incorrectly labelled step-up: its existing HTTP contract permits an act bearer and separately confirms irreversible choices. Onboarding names a future GitHub clone, not a local `repo` field; project selection/opening uses `path`.
