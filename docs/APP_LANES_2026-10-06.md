normal. A full check allocates `[flows: 1, app: 3, flows-real: 1, app-real: 1]`; a scripted-only check allocates

## Admission and isolation

- Warn, critical or unknown macOS pressure selects one app lane and logs the reason. Linux uses the existing swap
  signal; unknown swap readings also select one. Sticky macOS swap does not override normal kernel pressure.
- Every app start, including retries and starts that waited for a provider slot, checks the fresh pressure and lane
  limit inside the existing gate's lock. Rising pressure drains to one app lane; running journeys finish normally.
  The gate retains its memory reserve, recent-start accounting, critical-pressure stop, and first-provider-turn rule.
- Machines with at most 8 GiB retain their old release allocation, including a 7 GiB runner's full-check app lane.
  Environment overrides cannot bypass that ceiling, memory availability, pressure, or provider admission.
- Each group and retry keeps its own marked, cleaned-up temp root and existing OS-assigned ports. The lane root uses
  the short `so-e` prefix. The release wrapper no longer adds another temp directory around the browser runner.
  The socket regression passed with real subprocesses and canonical paths (99 bytes here, including Vitest's own
  temp-root level; limit 103). The port-selection code is unchanged; real parallel browser isolation remains unmeasured.
- Reports default to ignored `evidence/`. Each runner writes `lanes.json`: chosen count and reason, elapsed
  milliseconds, actual admission concurrency, whole process-tree peak RSS, system memory, and each group's elapsed
  time and sampled process-tree peak RSS. Sampling is every two seconds; unavailable process readings remain null.
